# dsh 同步（dsh-sync 扩展）

与 **dsh（DeepSeek Harness）数据目录**（默认 `~/.dsh`）**手动双向同步**模型配置与会话的 owc 官方扩展。

- 同步对象：dsh `profiles/<profile>/cordis.patch.yml` 里的 `llm-service-lite` 模型配置，以及 dsh 会话（`session.v3.jsonl.zstd`）。
- 方式：直读直写 dsh 数据目录文件，**不依赖 dsh 在线**；所有写操作都是你手动触发、逐项勾选后才执行。
- 面向对象：在 owc 与 dsh 之间来回使用同一批模型配置与会话的人。日常只用一个 harness 的话不需要打开它。

> 术语：**dsh** = DeepSeek Harness（上游 developer preview）；**owc** = OpenWebCode；**profile** = dsh 的配置档（默认 `web`）。

## 功能简介

dsh 同步扩展做两件事，各自**双向**、互不相干（两个区块各有独立的方向开关）：

| 区块 | 从 dsh 导入 | 导出到 dsh |
|---|---|---|
| **模型配置** | 读 `cordis.patch.yml` 的 provider/模型条目 → 写入 owc 模型目录 | owc 模型服务商 → 改写 `cordis.patch.yml` 的 `llm-service-lite` 段 |
| **会话** | dsh `session.v3.jsonl.zstd` → owc 会话（可继续对话） | owc 会话 → dsh 新会话目录 |

共同特点：

- **差异预览**：先「预览」，看清每一处差异/会话清单，再逐项勾选、执行；预览不会改动任何文件。
- **不静默丢弃**：同步中所有降级、丢弃、未映射字段都进执行报告（警告 / 未映射字段 / 丢弃事件计数）。
- **写前有保障**：改写 `cordis.patch.yml` 前自动备份；会话导出**永远只新建会话目录**，不覆盖 dsh 已有会话。
- **可继续对话**：会话为保真映射（不是只读归档），导入后能在 owc 继续，导出后能在 dsh 继续。

## 启用方法

**设置 → 扩展**，找到 **dsh 同步**（英文名 dsh Sync），打开开关。默认**关闭**。

启用后：

- 底部面板出现 **「dsh 同步」** 页签（未启用时不显示该页签）。
- 数据经扩展私有路由 `/api/ext/dsh-sync/*` 访问，受全局 `/api` 鉴权覆盖。
- 关闭扩展开关后页签立即消失，不再有任何 dsh 目录读写。

然后底部面板切到 **「dsh 同步」** 页签：

1. **环境状态** 区块先自动探测（「重新探测」可强制刷新）：数据目录是否存在、profile 文件是否存在、zstd 能力、dsh 是否在运行。
2. 在 **模型配置同步** 与 **会话同步** 两个区块里按需操作。

## 配置项

在 **设置 → 扩展 → dsh 同步** 的配置区填写：

| 配置项 | 默认 | 说明 |
|---|---|---|
| **dsh 数据目录** `dshHome` | `~/.dsh` | dsh 的数据目录。展开 `~` 为本机用户目录；填绝对路径亦可。 |
| **dsh profile** `profile` | `web` | 读取 `profiles/<profile>/cordis.patch.yml` 的模型配置（会话目录不区分 profile）。 |

留空即用默认值。两个字段都只影响「模型配置」区块对 `cordis.patch.yml` 的定位；会话区块始终扫描 `<dshHome>/sessions/`。

## 面板操作流

页签自上而下分三块：**环境状态**、**模型配置同步**、**会话同步**。两个同步区块各自是一个独立的方向开关 + 预览 + 勾选 + 执行 + 报告。

### 环境状态

只读探测结果，逐行显示：

- **数据目录**：`dshHome` 的实际路径；不存在时标黄提示「未检测到 dsh 数据目录」。
- **profile**：profile 名；`cordis.patch.yml` 不存在时标黄（只影响模型配置同步）。
- **zstd**：`node:zlib` 的 zstd 能力；不可用时标黄提示「需要 Node ≥22.15」，此时**会话同步不可用**（模型配置同步不受影响）。
- **dsh 正在运行**：探测到 dsh（默认 `127.0.0.1:3080`）在监听时给出信息提示（见[限制](#限制与注意事项)）。

### 模型配置同步

1. 选**同步方向**：`从 dsh 导入` 或 `导出到 dsh`。
2. 点 **「预览差异」**：读取对应侧配置，与另一侧比较，逐项列出并打三态徽标：
   - **新增**（绿）：目标侧缺失 —— 默认勾选；
   - **变更**（黄）：两侧都有但字段不同 —— **默认不勾**（冲突不隐式覆盖，需你显式确认）；展开「差异明细」可看 `字段: 现值 → 将写入值`；
   - **相同**（灰）：两侧一致 —— 不可勾选。
3. 底部条显示「已勾选 N / 总数」，按需勾选后点 **「执行同步」**。
4. **执行报告**：已应用 / 未执行计数与列表、警告、未映射字段（两侧对不上的字段，**不会**被同步）；导出方向还会列出：
   - **已备份原配置**：改写前生成的 `cordis.patch.yml.owc-sync-backup-<时间戳>` 路径；
   - **请在 dsh 环境设置以下变量**：写回的凭据是环境变量**引用名**（见[凭据处理](#凭据处理)），需你在 dsh 环境里设好对应变量。

> 写回 `cordis.patch.yml` 后，**dsh 需重启才生效**（dsh 运行中会在预览/报告里提示）。

### 会话同步

同样先选方向 `从 dsh 导入` / `导出到 dsh`，再 **「预览会话」**。执行前会写盘，所以预览与执行是两步。

**导入方向（dsh → owc）**：

1. 预览按 **工作目录（cwd）分组** 列出 dsh 会话，行内标注：代际、是否已同步过（「已同步 时间」）、带子代理转录（「子代理」）、消息/图片数。
2. 不可导入项被禁用并给出原因：**旧代际**（v0–v2，提示「需先在 dsh 中打开一次升级格式」）、**格式损坏**、**zstd 不可用**。
3. **缺 cwd 的会话**：预览里给每行一个「选择本机工作目录」输入框，填绝对路径（如 `/home/me/project`）后才能导入。
4. 默认勾选**可导入且未同步过**的会话；已同步过的默认不勾。
5. 勾选集里若含已同步会话，会出现 **「冲突处理」** 单选：
   - **覆盖更新已导入的会话**（`overwrite`）：改写映射表指向的 owc 会话历史；
   - **新建副本**（`new`）：另建一个 owc 会话（默认）。
6. 点 **「执行导入」**。报告含每条会话的标题与 user/assistant/tool 计数、图片降级提示、丢弃事件计数、警告、映射表落盘结果。

**导出方向（owc → dsh）**：

1. 预览列出 owc 会话（标题、provider/model、更新时间、上次导出时间「已导出 时间」）。
2. 导出条目**恒可勾选**，但**默认不勾**——批量全选可能一次写出大量会话，交由你显式选择（有「全选 / 清空」）。
3. 点 **「执行导出」**。每条 applied 报告含：写出的**事件数 / 附件数**、子会话徽标（见下）、降级警告；skipped 给出原因（如 cwd 不是绝对路径）。
4. 导出**只新增 dsh 会话目录**：重复导出 = 在 dsh 侧再生成一份新会话，**永不覆盖**已有会话。
5. **模型归属补全**：dsh 当前代际（v4）的会话校验要求每条 assistant 消息的 `provider`/`model` 都非空，而 owc 会话允许「只选了服务商、没选模型」。导出按会话现有信息补全：都非空 → 原样；有 provider 缺 model → 取该服务商在当前模型目录里的默认模型；缺 provider → 取 owc 当前默认（默认模型与会话里的模型一致才采用）；都缺 → 取 owc 当前默认。**补不出来该条即 skipped**（原因写明缺哪一半、要不要先去设置里选/配默认模型），不会写出一份 dsh 打开就报错的会话。

**子会话（子代理）报告小记**（导出方向）：父会话连同子代理转录一并导出时，applied 行显示 **「子会话 N 个」** 徽标；若个别子代理转录导出失败，额外显示一条黄色警示行（含失败的 taskId 与原因）——失败**不影响父会话本身导出成功**。

## 凭据处理

模型配置涉及 API Key，dsh 与 owc 的凭据形态不同，dsh-sync 在两侧之间做**语义转换**，全程避免明文外泄：

### 导入（dsh → owc）

- dsh 侧的 `apiKeyEnv`（环境变量**引用**）→ 读**当前 owc（扩展宿主）进程**的同名环境变量，取到值后**内联**写进 owc 服务商的 `apiKey`。预览里标注每个 key 的解析结论：
  - **已解析**：环境变量读到值；
  - **环境变量缺失**（红）：变量在 owc 进程环境里没有 —— 导入后需在 owc 设置里补填 API Key。
- dsh 侧内联的 `apiKey`（明文）→ **直通**写入 owc `apiKey`（预览标「内联凭据」）。
- 注意：扩展宿主进程的环境 = 启动 owc 的 shell 环境，所以想要解析成功，需在**启动 owc 的那个环境**里能看到对应变量。

### 导出（owc → dsh）

- owc 服务商凭据 → dsh `apiKeyEnv: OWC_SYNC_<服务商ID大写_SNAKE>_API_KEY`（ID 里非字母数字字符转 `_`；重名追加 `_2`/`_3`…）。
- **绝不写明文**：dsh 侧拿到的是环境变量**引用名**，你需要自行在 dsh 的运行环境里设置同名变量（值从 owc 设置页复制）。执行报告的「请在 dsh 环境设置以下变量」列出 `变量名 → 服务商 id` 清单。
- owc 侧服务商读取走 `providers.listProfiles`，**只回脱敏视图**（`hasApiKey`）——扩展进程**全程拿不到真实 Key**，因此导出只能给引用名。

### 两侧凭据结论徽标

导入：`已解析` / `环境变量缺失`（红）/ `内联凭据` / `无凭据`；导出：`环境变量引用` / `无凭据`。

## 限制与注意事项

- **会话仅支持 v3 代际**：只读写 `session.v3.jsonl.zstd`。旧代际（v0–v2）需先在 dsh 里打开一次升级格式；更新代际（>v3）明确拒绝（由 dsh 负责迁移链）。
- **`compaction/prune` 不映射**：dsh 的 `compaction/prune` 事件一律**丢弃并计数**（owc 的 `evicted` 账本条目与 artifact 落盘强耦合，只记录不驱逐会造成「账本说已驱逐、正文仍在」的不一致视图）。`compaction/summary` 会映射为 owc 压缩锚点（单条 compacted 语义，取最后一条）。
- **子代理配对是时序启发式**：dsh 子代理会话与父会话 `subagent` 工具调用的对应关系，按「两个序列的出现顺序一致」配对（上游未证实权威关联字段）。配不上对的子会话作为独立会话列入清单，配不上对的调用不挂字段——配对局限会写进报告。
- **zstd 需要 Node ≥22.15**：压缩会话的读写依赖 `node:zlib` 的 zstd 能力。能力不可用时环境状态条标黄，**会话同步整体不可用**（模型配置同步照常）。
- **写回 `cordis.patch.yml` 需重启 dsh 生效**：dsh 运行中改写，dsh 不感知；需重启 dsh 才用上新配置。
- **运行中检测与备份机制**：探测到 dsh 在运行（默认 `127.0.0.1:3080` 有监听）时给出警告提示但**允许**操作；改写 `cordis.patch.yml` 前自动复制为 `cordis.patch.yml.owc-sync-backup-<ISO时间戳>`。
- **改写只动 `llm-service-lite` 段**：以 CST 保注释方式改写 `profiles/<profile>/cordis.patch.yml` 里 `id: llm-service-lite` 条目的 `config.providers`，其余条目（含注释、`!!js` 自定义标签）原样保留。若你在 dsh 设置页保存过同一区块，可能覆盖本次改动——建议写完尽快重启 dsh 并核对。
- **dsh 头行不含 provider/model，模型归属写在 assistant 消息上**：导出时按会话当前 provider/model（缺项先按上节规则补全）写进每条 assistant 消息的 `source`，dsh 打开后以 dsh 当前模型配置继续对话。
- **模型配置为 manual 层**：导入的 dsh `models[]` 写入 owc 模型目录的 manual 层；映射不上的字段进报告「未映射字段」，不做猜测。
- **默认关闭**：扩展默认不启用，启用后也只在你点「预览 / 执行」时才读写文件。
